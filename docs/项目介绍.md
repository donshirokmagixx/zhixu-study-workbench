# 知序 · 学习复习工作台 —— 项目介绍

> 版本：v3.1（可运行 demo）
> 文档性质：面向使用者 / 评审者 / 后续开发者的项目全景说明
> 对应规格：`docs/开发规格与Agent提示词-v3.1.md`；架构设想：`docs/architecture.md`

---

## 1. 一句话说明

**知序**是一个单人使用、本地运行的一站式学习复习工作台：把课件、讲义、笔记等资料变成可检索的知识库，在上面做**有引用的答疑**、**可编辑可溯源的思维导图**、**有出处的成套练习题**，并顺手解决**论文格式检查与修正**。

它当前的形态是一个**能真实跑起来的 demo**，不是原型图：

| 维度 | 现状 |
|---|---|
| 运行方式 | `uvicorn app:app --host 127.0.0.1 --port 8788`，浏览器打开即用 |
| 数据 | 全部落在本机 `data/`（SQLite + 上传原件 + 导出文件） |
| 前端 | `web/index.html` 单文件，无框架、无 CDN、零构建 |
| 模型 | 任意 OpenAI 兼容端点（默认 DeepSeek `deepseek-flash`），Key 用 Windows DPAPI 加密 |
| 自动化验证 | `scripts/smoke.py` 30 项全通过（临时数据目录，不触碰真实数据） |

---

## 2. 它解决什么问题

学习复习的真实痛点不是"缺一个聊天机器人"，而是：

| 痛点 | 常见做法的问题 | 知序的处理 |
|---|---|---|
| 资料散落在 PDF / PPT / Word / 图片里 | 每次重新翻找，无法跨资料对比 | 统一入库 → 解析 → 切块 → 建立全文索引，按知识区隔离检索 |
| 直接问大模型，答案很流畅但不知道对不对 | 模型凭训练记忆回答，和你的课件无关 | 检索结果先组装成**证据包**，回答必须引用 `e1..e5`；无有效引用直接降级为"资料不足" |
| 复习时知识没有结构 | 手动整理提纲耗时 | 从文档标题层级**直接生成结构导图**（不花 token）；需要提炼时再用 AI 生成概念导图，每个节点可回链原文 |
| 出题靠手编或让 AI 乱发散 | 题目超出考纲、答案与解析对不上 | 固定 6 题、固定题型与难度、每题强制引用原文；LaTeX 公式转 Word 原生公式（OMML） |
| 课程论文格式反复被扣分 | 手动调字号行距、页码、目录 | 11 项格式检查 → 生成修正方案 → 确认后执行 → 保留原稿 + 输出修正稿与检查报告 |
| 多门课混在一起互相污染 | 一个会话里什么资料都塞进去 | 知识区（分区）+ 知识树（多级）+ 会话绑定范围，检索只在该范围内进行 |

## 4. 用户视角的完整流程

```
① 设置    填入 base_url / api_key / model → 测试连通 →（可选）PDF 转换自检
② 建知识区  「信号与系统」「数字电路」「大学物理」…… 互不干扰
③ 传资料   拖进 PDF/PPT/Word/图片 → 自动解析、切块、建索引 → 状态变"可用"
④ 提问    新建会话并绑定知识区 → 提问 → 回答带引用 → 点角标回看原文片段
⑤ 梳理    选资料生成导图（结构式秒出）→ 手动剪枝/改标题 → 保存 → 可重新生成且保留手改
⑥ 作业    论文：上传 DOCX → 检查 → 执行 → 下载修正稿/报告
          出题：选知识区（可挂导图）→ 生成 6 题 → 导出学生版 DOCX/PDF
⑦ 复盘    设置页看每次调用的 token 与耗时，估算成本
```

关键体验点：

- **引用可核**：角标展开是原文片段，不是"模型觉得应该在这里"；资料被删除或重建后，引用会标记为 `snapshot / drifted / missing`，不假装还在。
- **范围可控**：会话绑定知识区（可再绑到某个知识树节点），检索物理上只在该范围里做，不存在"混库污染"。
- **资料不足要说**：检索不到证据时直接返回"当前知识区没有找到能回答该问题的资料"；模型给了回答但没给有效引用时，回退为"模型没有给出可核对的资料引用，本次回答不作为资料结论"。

## 5. 系统架构（实际形态）

第一版刻意做成"单进程 + 单文件前端"，没有引入消息队列、向量库、容器编排。原因很直接：**单人单机、资料量小、部署要双击即用**。架构留了扩展位，但不提前付运维成本。

```
┌─────────────────────────────────────────────────────────────┐
│ 浏览器：web/index.html（单文件，无框架无 CDN）                 │
│   聊天首页 · 知识库 · 导图 · 作业 · 设置                        │
└───────────────────────┬─────────────────────────────────────┘
                        │ 同源 HTTP（仅 127.0.0.1:8788）
                        │ 中间件：Host 白名单 / 跨站拦截 / 25MB 上限 / 安全头
┌───────────────────────▼─────────────────────────────────────┐
│ app.py —— FastAPI 唯一入口，36 个 /api 接口                    │
│  只做：读参数 → 调模块 → 落库 → 错误码映射 → JSON              │
└───┬──────────┬──────────┬──────────┬──────────┬──────────────┘
    │          │          │          │          │
┌───▼────┐┌────▼─────┐┌───▼─────┐┌───▼────┐┌───▼──────────┐
│rag.py  ││mindmap.py││quiz.py  ││paper.py││officedoc.py  │
│解析/切块││M1/M2 导图││6 题成卷  ││11 项检查││DOCX→PDF(COM) │
│检索/证据││溯源/合并 ││公式/导出 ││修正/报告││Word→WPS 回退 │
└───┬────┘└────┬─────┘└───┬─────┘└───┬────┘└───┬──────────┘
    │          │          │          │         │
    └──────────┴────┬─────┴──────────┴─────────┘
                    │
        ┌───────────▼────────────┐   ┌─────────────────────┐
        │ llm.py  模型与 Skill 层 │──▶│ OpenAI 兼容端点       │
        │ JSON 校验/重试/用量记录  │   │ （DeepSeek 等云端）   │
        └───────────┬────────────┘   └─────────────────────┘
                    │
        ┌───────────▼───────────────────────────────────────┐
        │ db.py  SQLite（WAL）14 张实体表 + FTS5 虚表            │
        │ config.py  路径/常量/DPAPI 密钥  tree.py 知识树     │
        │ data/：app.db · uploads/ · exports/ · tmp/         │
        └───────────────────────────────────────────────────┘
```

设计原则（也是后续扩展的约束）：

1. **`app.py` 只做接口层**，解析、检索、导图、出题、论文逻辑都在各自模块，任何业务改动不需要动路由。
2. **`llm.py` 是唯一的模型出口**，业务模块不直接发 HTTP；换厂商只改设置页配置。
3. **解析一次，处处复用**：`chunks` 同时服务问答、导图和出题，避免三套索引语义漂移。
4. **Skill 即产品逻辑**：提示词放在 `skills/*/SKILL.md`，按 `sha256[:12]` 记录到每次用量里，能追溯"这条回答是哪版提示词产生的"。

## 6. 核心机制详解

### 6.1 资料解析与切块（`rag.py`）

| 格式 | 解析方式 | 保留的结构信息 |
|---|---|---|
| PDF | PyMuPDF 逐页取文本；无文本层判定为扫描件 → 200dpi 渲染 + OCR | 页码 |
| 扫描 PDF / 图片 | rapidocr（onnxruntime，本地离线） | 页码（图片记为第 1 页） |
| DOCX | python-docx；识别 `Heading 1..3` / `标题 1..3` | `heading_path`（祖先标题用 ` > ` 连接） |
| PPTX | python-pptx；每页标题 + 正文 + 演讲备注 | 页码 = slide 序号，`heading_path` = 页标题 |
| MD | 自研行扫描（识别代码围栏，避免把 `#` 注释当标题） | `#` 层级 → `heading_path` |
| TXT | UTF-8 失败回退 GBK | 无层级，整篇为一个 section |

切块规则（`config.py` 可调）：

- 同一 `heading_path` 的相邻 section 若 < 600 字则合并，合并后不超过 800 字；
- 超过 800 字按 100 字重叠滑窗切分；
- 每个 chunk 写入 FTS5 时**把 `heading_path` 拼在正文前**，这样"第 5 章讲什么"这类按章节名的提问也能召回。

产物：`documents`（状态 `ready / ready_with_warning / failed`）+ `chunks`（正文、页码、章节路径、`text_sha256`）+ `chunks_fts`（中文 bigram 倒排）。

### 6.2 检索与证据包

检索不是"把全部资料塞给模型"，而是一套有预算的管线：

```
问题
 ├─ 清洗：去掉"请帮我/是什么/怎么"等口语套话（否则无关页被顶上）
 ├─ 扩展：术语同义词表（导数↔求导↔微分、混叠↔奈奎斯特…），最多 18 个候选
 ├─ 召回：FTS5 MATCH（bigram）→ bm25 排序取前 40
 ├─ 重排：1/(名次+1) 基础分 + 题名/章节命中加权 + 表格类问题对含表 chunk 加权
 ├─ 去重：按 text_sha256 去掉重复片段，取前 5
 └─ 证据包：编号 e1..e5，带 document_id / chunk_id / page / section / content_hash
           总字符 ≤ 4500，超出截断并标记
```

关键参数（`config.py`）：`RETRIEVE_TOP=40`、`RETRIEVE_FINAL=5`、`CONTEXT_MAX_CHARS=4500`、`MAX_EVIDENCE_TOKENS=3000`。

**为什么先做词法检索**：本地零成本、无嵌入模型依赖、启动即用；代价是同义改写能力有限，已用同义词表 + 章节路径前缀部分弥补。向量检索在路线图里。

### 6.3 回答的可信度控制

模型被要求返回结构化 JSON，服务端逐项校验后才落库：

| 字段 | 校验 | 失败处理 |
|---|---|---|
| `status` | 必须是 `answered / partial / insufficient_evidence / needs_parse / blocked_scope` | 抛 `model_output_invalid` |
| `answer` | 非空字符串 | 同上 |
| `citations` | 每个 id 必须存在于本轮证据映射中 | 非法 id 丢弃 |
| 组合条件 | `status=answered` 但无有效引用 | 强制降级为 `insufficient_evidence` 并替换为固定文案 |

多轮追问：只取同会话最近 6 条消息（每条截断 400 字）作为"理解指代"的上下文，并明确告知模型**它不是事实来源**；检索时把上一轮问题拼进查询词，减少"它/这个"导致的召回丢失。

### 6.4 思维导图：两种模式

| | M1 结构式 | M2 概念式 |
|---|---|---|
| 输入 | DOCX / MD / PPTX（必须有标题层级） | 任意已入库资料，或一张导图 |
| 过程 | 读 `heading_path` 建树，**不调用模型** | 取证据（每文档前 12 个 chunk，总 ≤40 且 ≤12000 字）→ 调 `mindmap-builder` skill |
| 成本 | 0 token，毫秒级 | 一次模型调用 |
| 校验 | 无（结构来自原文） | 单一根节点、id 唯一、parent 存在、无环、可达；节点 ≤120、深度 ≤5；`refs` 必须是本轮 `evidence_id`，否则该节点 `unverified=1` 且清空来源 |
| 适用 | 教材、规范文档，要"忠于原文" | 需要提炼要点、重组逻辑 |

编辑与再生成：

- 用户可增删节点、改标题/备注、移动父节点（≤300 节点）；根节点不可删除或改名，服务端做环检测；
- 被用户改过的节点记为 `origin=user`；**重新生成只覆盖 `origin=ai` 的节点，手改内容保留**，因来源变化而消失的手改节点会挂到根并追加 `[来源已变更]`。

### 6.5 出题与公式

- 默认保持旧版固定 6 题；新界面可分别设置单选、多选、判断、计算题数量（每种 0–10，总计 1–20），后端严格校验题型顺序与数量；
- 新增 `experienced-teacher-examiner` Skill，与原有 `grounded-quiz-generator` 一起注入：负责命题蓝图、教师式干扰项、难度递进、答案解析终审；证据边界仍由原 Skill 约束；
- 新增 `bupt-exam-style` Skill：依据 10 套公开校内试卷的结构统计，校准 5–9 个分组、客观题与综合题配比、多小问递进、题干长度和公式/图形条件；用户设置的题型题量始终优先；
- 每题必须给出 `citations`，且必须是证据包里的 `evidence_id`，否则整卷校验失败并触发一次纠错重试；
- 可挂一张导图：只把"有来源且已核对"的节点标题作为**考点线索**传入，命题仍必须回到证据；
- 题干、选项、答案、解析中的 `$...$` 与主公式 `latex` 均校验定界符、花括号、乱码及 MathML 转换；非法输出触发一次纠错，不直接落库；
- 页面使用服务端生成的安全 MathML 预览；导出学生版 DOCX 时经 `latex2mathml + mathml2omml` 转成 **Word 原生公式（OMML）**，转换失败会停止导出并提示，不再静默输出可疑公式文本；
- PDF 由 `officedoc.py` 通过 Word COM 转换，失败自动回退 WPS COM（子进程 + 超时隔离 + 残留进程清理）。

### 6.6 论文格式检查与修正

两阶段设计，避免"一上传就被悄悄改文件"：

```
上传 DOCX → create_job（记录 sha256）
   ↓
POST /check  → 11 项检查（字体/字号/行距/首行缩进/对齐/标题层级/图表题注/页边距/页码/目录/空白段…）
             → 程序规则 + 可选模型复核 → issues 列表 + 待执行方案（不写文件）
   ↓
人工确认
   ↓
POST /execute → 按白名单执行 6 类修正 → 校验（文本序列/对象数量）→ 原稿保留 + 修正稿 DOCX/PDF + 检查报告
```

模板来源：内置 `skills/paper-format-corrector/assets/generic-cn-course-paper-v1.json`，或在请求里传自定义 `profile_json`（深合并覆盖）。每次检查记录模板 `digest`，执行时校验一致，防止"按 A 模板检查、用 B 模板执行"。

## 7. 数据模型

SQLite，14 张实体表 + 1 张 FTS5 虚表，全部在 `db.py` 的 `SCHEMA` 中定义，启动时自动建表并做**只加列不重建**的兼容迁移。

| 分组 | 表 | 关键字段 | 作用 |
|---|---|---|---|
| 组织 | `zones` | `name UNIQUE` | 知识区（分区） |
| 组织 | `knowledge_nodes` | `zone_id, parent_id, name` | 知识树，可多级；用于限定资料与会话范围 |
| 资料 | `documents` | `sha256, status, warning, page_count, chunk_count, quality, quality_note` | 资料主记录、解析状态与解析质量分 |
| 资料 | `chunks` | `heading_path, page, text, text_sha256` | 检索与溯源的最小单元 |
| 资料 | `chunks_fts`（虚表） | `chunk_id, text_bigram` | 中文 bigram 全文索引 |
| 对话 | `conversations` | `zone_id, node_id, title` | 会话与范围绑定 |
| 对话 | `messages` | `role, content, status` | 消息；`status` 记录可信度结论 |
| 对话 | `citations` | `chunk_id, page, heading_path, snippet, text_hash` | 引用快照 + 原文哈希（用于检测漂移） |
| 导图 | `mindmaps` | `mode(structure/concept), generated_by(llm/rule)` | 导图元信息与生成来源 |
| 导图 | `mindmap_nodes` | `node_key, parent_key, source_chunk_ids, origin, unverified` | 节点 + 来源 + 归属（ai/user） |
| 出题 | `quizzes` / `quiz_questions` | `type, stem, options, answer, explanation, citations, latex` | 试卷与题目 |
| 论文 | `paper_jobs` | `sha256, profile_digest, status, issues, operations, checks` | 作业状态机与产物路径 |
| 运营 | `usage_logs` | `kind, model, tokens, latency_ms, ok, skill_name, skill_sha256` | 成本与可观测 |
| 运营 | `settings` | `key, value` | 预留键值配置 |

数据一致性要点：

- 删除资料 = 删 chunks + FTS 行 + 引用保留（转为快照语义）+ 删上传文件；
- 解析/重建索引后写入 `quality` 与 `quality_note`；低质量资料保留可查，只在检索排序中降权，不自动删除；
- 引用通过 `text_hash` 反查当前 chunk：命中为 `current`，章节能找到但片段已变为 `drifted`，找不到为 `missing`；
- 所有写操作经 `db.x / db.xmany`，读经 `db.q / db.q1`，不裸连 SQLite。

## 11. 安全与隐私

| 项 | 做法 |
|---|---|
| 网络暴露面 | 仅允许 `127.0.0.1 / localhost / ::1` 的 Host；拒绝 `Sec-Fetch-Site: cross-site` 与来源不一致的请求；API 响应 `Cache-Control: no-store` |
| API Key | Windows DPAPI（`CryptProtectData`）加密后写 `data/config.json`；旧明文配置启动时自动迁移；接口只回掩码 |
| 资料内容 | 原文不写日志；引用片段存库用于溯源 |

仍需注意：一旦调用云端模型，**证据片段会随请求发给该厂商**。项目不提供"零外发"模式（本地模型未接入），隐私敏感资料请自行评估。

## 12. 已知限制

实现层已确认的限制（不是猜测）：

1. **无流式输出**：生成期间只有阶段性提示，长回答体感等待明显；
2. **检索是词法匹配**：FTS5 bigram + 同义词表，没有向量语义检索，换个说法可能召回不到；
3. **OCR 只处理前 30 页**：扫描件超过 30 页会截断并给固定 warning；手写体与公式识别不保证；
4. **PDF 导出依赖本机 Office**：Word/WPS 都不可用时返回 `pdf_engine_unavailable`，DOCX 仍可用；
5. **仅桌面布局**：≥1280px，没有移动端适配；
6. **导图 M2 的合并粒度**：改过 `title` 的节点在重新生成后可能以新节点形式出现（按 `node_key` 合并的固有限制）；
7. **`mindmaps` 表不存 document_ids**：重新生成时从节点来源推断资料范围，推不到会回退为整个知识区；
8. **M2 会自动回退**：模型截断会自动加倍 token 重试一次；仍失败、请求失败或未配置模型时，返回 `method="rule"` 的规则版导图并在界面提示原因，规则版结构弱于 AI 概念图；
9. **质量分是启发式规则**：按乱码率、有效字符占比等打分，只能提示解析可读性，不能判断内容正确性；低质量资料检索最多降权 50%，不阻止引用；
10. **导出为客户端生成**：导图 SVG/PNG 由浏览器从当前可见画布生成，不包含隐藏子树，也不是可继续编辑的源文件；试卷只有学生版；
11. **论文长文**：超过 240 段的摘要处理上限；纯文本旧目录不一定被替换，报告会提示按 F9 更新；
12. **课堂录音依赖浏览器语音服务**：使用 Web Speech API，需 Chrome/Edge、麦克风和网络；项目不保存音频文件，转写仅在页面内存中，写入正文后才随笔记保存；
13. **课堂摘要只依据转写**：不引用课件、不补充老师未讲内容；转写识别错误会传导到摘要，需人工核对；
14. **依赖未锁版本**：`requirements.txt` 只写包名，重装可能装到新版本（已实测当前组合可用）。

## 14. 术语

| 术语 | 含义 |
|---|---|
| 知识区（zone） | 顶层分区，如"信号与系统"；检索与导图都以它为边界 |
| 知识节点（node） | 知识区内的多级树；资料与会话可挂到节点，检索范围可进一步收窄 |
| chunk | 切块后的最小检索单元，带页码与章节路径 |
| 证据包（evidence pack） | 送给模型的 `e1..e5` 片段集合，含来源、定位与预算信息 |
| `heading_path` | 祖先标题链（`第5章 > 5.1 熵 > 熵增原理`），用于导图建树与检索加权 |
| `origin` | 导图节点归属：`ai`（可被重新生成覆盖）或 `user`（保留手改） |
| `unverified` | 导图节点未能对上有效来源的标记 |
| M1 / M2 | 结构式导图（不调模型）/ 概念式导图（调模型） |
| OMML | Office Math Markup Language，Word 原生公式格式 |
