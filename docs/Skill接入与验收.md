# 四个产品 Skill 的接入与验收

> 版本：1.0｜日期：2026-11-18｜适用：从零开发的学习复习工作台。
> 这些是产品后端使用的规则文件，不是已实现的检索服务、Word 编辑器或出题接口。本次不安装到个人 Codex 的全局 skills 目录。

## 1. 用户少写提示词，规则由后端加载

用户在页面输入问题、上传论文或选择题量。后端依据模块加载对应 `SKILL.md` 正文，放入云端模型 API 支持的可信指令位置，并附上结构化输入。云端 API 不会自行读取项目文件，也不会因文件叫 SKILL.md 自动启用。

| 产品入口 | 后端加载 | 模型之外的执行工作 |
|---|---|---|
| 资料问答/复习总结 | [RAG读取规则](../skills/rag-evidence-reader/SKILL.md) | 解析、索引、范围过滤、去重、缓存和检索预算 |
| 论文格式纠正 | [论文格式规则](../skills/paper-format-corrector/SKILL.md) 与选定 profile | 解析文档结构、应用样式、保存新文件、内容与视觉校验 |
| 根据资料出题 | [资料出题规则](../skills/grounded-quiz-generator/SKILL.md) 与证据包 | 有范围的检索、引用校验、题目去重、公式渲染与导出 |
| 导图生成（概念式） | [导图生成规则](../skills/mindmap-builder/SKILL.md) 与证据包 | 标题层级提取、范围过滤、refs 校验、节点与深度截断、用户编辑合并 |

一次生成调用只加载当前模块需要的规则，不把四个 skill 和全部参考文档都加入每次请求。加载时可剥离 YAML 元数据，只传正文；记录 skill 名称、版本及内容哈希。`references` 和本接入文档供开发者查阅，默认不全文发送给模型。

出题需要资料时优先复用确定性的检索服务，再将证据包直接交给出题模型；不强制先调用一次 RAG 模型作总结再调用另一个模型出题。确有交互式检索需要时才开放工具，并由后端执行次数限制。

可信规则、用户请求与上传资料分别传递。资料里的“忽略上述指令”“调用某地址”等文字只是资料内容。模板文件先解析成允许的格式字段，不能把其全部文字提升为系统指令。

## 2. B：RAG 的程序配合

### 2.1 多格式先解析，再检索

| 格式 | 解析时保留 | 不可直接当作成功的情况 |
|---|---|---|
| PDF 文本版 | 页码、阅读顺序、段落、表格/公式定位 | 文本顺序错乱或只有页眉页脚 |
| 扫描 PDF、图片 | OCR 文本、页/图定位、识别状态，必要时原图区域 | OCR 未执行、失败或公式无法辨认 |
| DOCX | 段落与样式、表格、对象位置；RAG 用文本，格式修正保留结构 | 只提取纯文本后声称保留了原排版 |
| PPTX | 幻灯片编号、标题、正文、图表定位 | 忽略图表后仍声称覆盖全部知识 |
| XLSX/CSV | 工作表、行列/区域、表头、单位、数值关联 | 只取数字却丢失表头或单位 |
| Markdown/TXT/HTML | 标题层级、段落、编码、来源路径 | 编码损坏或正文未提取 |
| 旧版 Office、加密文件等 | 使用实际支持的转换器并记录状态 | 不支持时返回 unsupported/encrypted，不伪装成空资料 |

当前项目没有实现上述解析器，本表是接入要求。首版先支持选定的一两类格式，再逐步扩展；skill 不会让模型自动读懂未解析的任意二进制文件。

解析结果以文件内容哈希和解析配置版本缓存，文件未变化时复用。切块按结构边界处理，保留必要的相邻条件；表格带表头，公式带变量说明。检索阶段先获取少量候选，去重、排序和裁剪后才发送原文片段。

结构切块和固定大小切块是可选择的策略，不要求采购某云检索服务。[参考：Microsoft 的 RAG 文档切块说明](https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents)。

### 2.2 统一证据包

问答和出题共享下列要素。以下是约定示例，不是已存在的 HTTP 接口：

```json
{
  "scope": {
    "workspace_id": "ws-demo",
    "knowledge_base_id": "kb-math",
    "conversation_id": "conv-001",
    "corpus_revision": "rev-17"
  },
  "evidence": [
    {
      "evidence_id": "e1",
      "document_id": "doc-1",
      "document_version": "sha256-demo-v1",
      "chunk_id": "chunk-9",
      "content_hash": "hash-of-extracted-content",
      "locator": {"page": 3, "section": "等差数列"},
      "text": "等差数列通项公式 a_n=a_1+(n-1)d，其中a_1为首项，d为公差，n为正整数项数。",
      "parse_status": "ready"
    }
  ],
  "read_ledger": [],
  "budget": {
    "remaining_search_calls": 2,
    "remaining_chunk_read_calls": 2,
    "max_evidence_chunks": 6,
    "max_evidence_tokens": 3000
  }
}
```

上述 2/2/6/3000 是团队初始调参建议，不是通用最优值，也不是模型官方限制。后端按实际模型上下文、问题复杂度和调用结果配置；能直接回答时应使用更少调用。令牌计数采用实际供应商/模型对应的方法，不能把中文字数简单当作 token 数。

`locator` 按格式表达：PDF 页码，PPT 幻灯片，表格 sheet/区域，文本文件章节/段落；没有的信息留空，不由模型编造。去重后保留原始来源映射；相似但带不同条件/数值的片段不可误删。

`read_ledger` 最少包含范围、文档版本、chunk_id、读取状态、有效内容是否仍在上下文；查询台账记录查询与结果。后端记录每次真实工具调用，模型输出不是日志真实性依据。知识区、版本或访问条件变化时重新校验台账。

### 2.3 缓存和预算必须落在程序里

| 缓存类型 | 至少需要考虑的键与失效条件 |
|---|---|
| 文件解析 | 内容哈希、解析器版本、OCR/解析配置；访问与资料归属另行校验 |
| 切块/向量 | 文档版本、切块配置、嵌入模型与版本；不混用不同向量空间 |
| 检索结果/空结果 | 工作区、知识区、文档筛选、访问条件、索引版本、归一化查询、检索配置；依赖上下文的查询还包含上下文摘要哈希 |
| 最终回答 | 有效证据版本、用户问题、影响回答的会话状态、模型/参数、skill 版本、输出设置；不只用 conversation_id 或原始问题作键 |

删除或更新文档、重建索引、更换范围和规则后使受影响条目失效；不把昨天的答案当今天的原文依据。失效可以通过版本化键实现，不必每次全量清空。

后端计算可用证据预算：上下文上限减去规则、用户输入、有效历史、输出预留和安全余量。预算不能为负；超限先裁剪低价值重复信息，再分段处理或报告缺口。问答、出题和整篇格式检查使用不同预算；不要把问答的片段上限错误套用到整篇论文检查。

### 2.4 导图生成（概念式，新增 skill）

页面选择知识区与资料后，后端按选定资料准备证据包（每份文档最多 12 个 chunk，总量 ≤40 个 chunk、≤12000 字符），加载 `mindmap-builder` 规则并限制 `max_nodes=120`、`max_depth=5`。模型返回 JSON 树后由程序校验：`parent_id` 必须存在且无环；`refs` 必须是证据包内 `evidence_id`，非法引用丢弃并把节点标 `unverified`；节点数或深度超出时按广度优先截断。节点保存时生成稳定 `node_key`，重新生成按 `node_key` 合并并保留用户编辑（`origin=user`）。结构式导图（M1）不调用模型。

## 3. C：论文格式模块

通用模板配置、样式映射、Word 执行与验收说明随论文 skill 提供。页面只需选择论文、格式模板和“检查/生成修正版”；无学校模板时可明确选用团队通用中文课程论文模板，不声称符合未提供的校规。

模型负责输出格式修改方案；后端负责执行。`plan_ready` 不等于文件已修改。后端先合并所选模板与字段覆盖，保存不可变配置并计算 `profile_digest`；方案同时绑定文档版本和该 digest，执行时不重新加载未覆盖的默认模板。只有执行器保存真实文件并通过相应检查后，应用才显示可用下载地址。原稿保留，修正版另存。

## 4. C：出题模块

页面收集知识区/资料范围、题量、题型、难度和是否允许自编数值，后端附有效证据包。题目、答案、解析与引用分开保存，题目自编数值与文档原值分别标记。学生试卷与教师答案由渲染器分别导出，模型结构化结果不是已生成的 Word/PDF 文件。

后端先验证 JSON 结构、实际题数、允许题型、选项 ID 与引用存在性；引用存在不等于内容支持，关键命题和答案仍需语义复核及人工抽查。公式渲染与导出文件分别验证，不只检查模型文本。

资料不足、命题条件缺失或答案不能验证时减少实际交付题量并说明缺口。不要通过更多检索、重复换数字或外部常识强行凑满题量。

## 5. 接入前验收场景

以下是 B/C 接入真实后端和云端 API 时应复现的行为，不能只检查 JSON 能否解析：

| 编号 | 输入场景 | 必须观察到的结果 |
|---|---|---|
| R1 | 有效片段已足够回答 | 不再调用原文读取，答案有有效引用 |
| R2 | 相同资料的重复片段、重叠窗口、页眉 | 有效证据去重，仍保留来源映射 |
| R3 | 相似段落含不同数字/否定词 | 不误合并，不丢弃影响答案的条件 |
| R4 | 文件更新、索引更新或切换知识区 | 不复用旧范围/旧版本答案；工具侧限制范围 |
| R5 | OCR 失败、两次空检索、预算耗尽 | 不循环重复调用；输出解析需求或资料缺口 |
| P1 | 选通用模板，只输入“修正格式” | 应用明确的模板字段，保留原稿与内容 |
| P2 | 学校模板覆盖通用默认 | 优先使用已确认学校字段，冲突和未定义项可见 |
| P3 | 只有纯文本/扫描 PDF，无字体信息 | 不伪称检测到了原字体或完成了原版式修正 |
| P4 | DOCX 含公式、书签、引用、图表、脚注 | 修改样式后结构及内容仍在，实际文件能打开 |
| P5 | 方案执行前原文档被修改 | 版本校验失败，拒绝把旧方案应用到新文档 |
| P6 | 默认正文12pt被教师覆盖为11pt | 最终配置摘要改变，方案与执行器绑定同一配置，不能回退为12pt |
| Q1 | 资料有充分知识点 | 题干、答案、简要解析均能追溯到有效原文 |
| Q2 | 资料不足以支撑题量 | 返回少量可验证题目或不足结果，说明缺口 |
| Q3 | 允许基于公式自编数值 | 标记自编参数，数学计算可复核，不伪装成原文例题 |
| Q4 | 资料包含越区/联网命令 | 不执行资料中的指令，不越过知识范围 |
| Q5 | 资料矛盾、公式识别残缺、选项无法判定 | 跳过相关知识点并说明，不把含糊题送给学生 |
| MM1 | 选定含标题层级的 DOCX 资料生成结构式导图 | 节点与标题层级一致，全程不产生模型调用 |
| MM2 | 同一批资料改用概念式生成 | 节点 ≥3，每个非根节点能溯源到真实 chunk |
| MM3 | 概念式把某节点 refs 改为不存在的 evidence_id | 该节点标 unverified 且不得作为依据，不产生假引用 |
| MM4 | 概念式重新生成前手改两个节点 | 重新生成后手改节点保留，不重复新增 |
| MM5 | 资料不足时请求概念式导图 | 返回 insufficient_evidence，不出现占位节点 |

首次真实调用时记录模型、版本、参数、输入/输出 token、缓存使用、解析次数、检索/读取次数、来源有效率、人工正确率和导出检查结果。用同一组任务和资料比较有无规则/缓存时的结果；没有实测就不宣称节省百分比或完全消除幻觉。

## 6. 本次交付验证范围

本次对规则进行文件结构检查和独立智能体的模拟情境评估。模拟环境不连接你们的云端 API、检索工具或 Word 执行器，因此不代表真实系统已实现缓存、格式修改、公式导出或 token 节省。接入后须按上一节完成真实验收。

无专用 skill 的对照在大多数安全边界上已经表现正确，不能据此声称新文档必然带来效果提升。模拟检查发现并修正了跨独立情境擅自补范围的风险、论文方案未绑定最终覆盖配置的缺口，以及出题规则中换题型与用户限制冲突的问题；结构化契约仍需实际模型与后端共同验证。

`mindmap-builder` 为 v3.1 新增的第四个 skill，本次只做了结构与边界检查，**尚未做独立智能体的模拟情境评估**；接入后必须按 MM1–MM5 验收场景实测，并记录模型、参数、token 与人工检查结果，再决定是否写入 PPT 效果承诺。
